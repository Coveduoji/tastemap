# 中心标点、收藏面板和性能优化

## 行为

- 主地图始终显示固定中心标点，可点击打开当前位置的收藏流程；它属于选点控件，不计入收藏聚合。
- “我的收藏”使用标准Flutter可拖动面板，保留城市折叠；选择地点后收起面板，地图放大显示该地点，不自动打开详情。
- 个人页收藏条目及“查看全部”也将选择结果返回主地图，避免不同入口的行为不一致。

## 性能与动效

- 详情面板不再逐帧调整原生地图纹理尺寸、重建整页；地图保持固定大小，打开详情时使用SDK自带相机移动将地点放到可见区域。
- 地图拖动结束只更新中心坐标，跨越行政聚合层级时才触发相关界面重建。
- 单点标记位图按图标与状态复用，不再为每个地点名称生成同样的PNG。
- 收藏列表使用Flutter SliverList按需构建，城市折叠能力保留。
- 面板使用统一进入/退出时长及标准吸附动画；中心标点使用轻量缩放反馈。地图和固定标点分开重绘。
- 使用标准Flutter profile构建进行真机性能验证，沿用同一预览包标识与调试签名，保留数据；不拿debug模式的观感代表最终运行性能。

## 成熟地图依赖的最小补丁

本轮真机排查确认 amap_map 1.0.15 的 Android 相机移动分支缺少 result.success，导致等待其 Future 的逻辑无法继续，详情关闭后主界面也可能停在隐藏控件的状态。本地保留原库运行代码和Apache-2.0许可，仅修补此回执，以及原库误将海拔按纬度范围校验的问题。详情关闭清理另与相机调用解耦。来源与变更见 third_party/amap_map/LOCAL_PATCHES.md；未自建平台桥。

## 定位修复

真机复测发现地图蓝色位置图层显示正常，但应用依赖其回调等待结果时会超时。定位结果改为通过现成amap_location_flutter 1.0.0的单次定位结果流获取，继续复用同一个高德原生SDK和Key，不自建平台桥。用户同意高德服务、授予系统位置权限后才发起定位。

## 验证

- 静态分析无问题，18项测试通过。
- 新增/补充回归检查覆盖地图铺满、中心标点及点击目标、城市折叠、选择返回地点且不打开详情、面板下拉关闭。
- 1000条收藏的测试中，首次只构建可见区域附近的条目（少于40个ListTile）。
- Android16真机性能构建验证：固定中心标点可点击打开附近收藏；下拉可关闭。
- 我的收藏以城市分组面板展示，选择“阳光花城同馨苑”后面板收起，地图放大到该点，没有自动打开详情。
- 搜索星巴克进入详情，目标标记位于面板上方；展开、下拉关闭后主界面控件和中心标点恢复。
- 从廊坊异地地图点击定位，已返回上海设备当前位置。
- 数据库逐行比对：原2条places、2条collections均保持不变，没有留下测试收藏。
- 最终性能构建已安装，截图见 docs/device-performance。帧率提升未做百分比量化。

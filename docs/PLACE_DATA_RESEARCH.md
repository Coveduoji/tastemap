# 地点详情的数据来源方案

调研日期：2026-11-01。以下区分公开产品能力与本项目已接入内容，未将未授权接口写成可用功能。

| 方案 | 能补充什么 | 接入条件与适配结论 |
| --- | --- | --- |
| 高德 POI 2.0 | 商圈、特色、今日/每周营业时间、楼层、子地点、照片及已有商户字段 | 已有 Key，优先补齐；不同类型/权限返回不同字段，不是完整评论或攻略数据库。[官方字段说明](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) |
| 百度地点详情 3.0 | 介绍、建议游玩时长、最佳时间、品牌、楼层、子点；照片需申请对应权限 | 适合补充景点及商户内容。官方明确照片需要商用授权后提交申请；实际字段覆盖需用获授权 Key 确认。推荐作为第二来源候选。[官方文档](https://lbsyun.baidu.com/docs/webapi?title=placev3%2Fguide%2Fwebservice-placeapiV3%2FinterfaceDocumentV3) |
| 美团/点评 | 到店商品、商户服务等合作生态能力 | 已查到的是面向合作方的业务授权，不足以证明可直接批量获取任意地点的用户评论。评论内容需确认具体合作范围后接入。[合作能力中心](https://developer.meituan.com/ability-center/list) |
| 携程玩乐开放平台 | 景点门票和玩乐商品内容、供应与分销接口 | 面向供应商、分销合作伙伴。适合有票务合作需求时再接入；不能把商品接口当作所有景点攻略/评论的开放接口。[官方公告](https://ttdopen.ctrip.com/apiplatform/help-detail.do?no=88) |
| Wikimedia | 有百科条目的地标、博物馆等简介 | 可用成熟 MediaWiki API 获取坐标及摘要，但普通门店覆盖有限；文本和媒体需按各自许可署名，客户端网络可达性仍需评估。适合景点补充，不能承诺所有地点都有简介。[坐标 API](https://www.mediawiki.org/wiki/API:Geosearch)、[摘要 API](https://www.mediawiki.org/wiki/Extension:TextExtracts)、[使用条款](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use) |
| Google Places | 海外地点资料、照片、评论等 | 当前产品继续用高德底图，Google 的地图展示规则不适合作为此处的直接混合图层方案，不作为本轮选择。[官方展示政策](https://developers.google.com/maps/documentation/places/web-service/policies) |

## 推荐落地顺序

1. 本轮先完整读取现有高德字段，增加真实子地点和周边地铁/公交/停车设施，详情面板可拖动，下层保持周边地图。
2. 若主要需要景点介绍、时长和玩法，优先确认百度地点详情3.0的商业权限与实际样本覆盖。取得权限后再接入，不添加未配置的空壳 Provider。
3. 若主要需要用户点评、门票商品，走点评/携程对应合作流程；可先链接原平台，由用户查看完整内容。
4. 百科资料仅在明确匹配到同一地标时补充，保留文章来源和许可，不将品牌百科套用到单家分店。

跨源匹配应综合名称、分店后缀、行政区、地址、距离和电话。坐标使用各供应商声明的坐标系转换；不能仅靠同名判定同一家店。来源评分不相加或平均，营业时间等冲突字段保留来源。若新增付费服务，优先通过已有成熟后端托管服务保护凭证、按供应商许可管理缓存，无必要不自建通用数据框架。

## 本轮开发交付

- 已扩展高德详情请求和解析：商圈、特色、每周营业时间、楼层、停车类型、别名、子地点，以及周边交通。
- 未接入百度/点评/携程的未授权内容，也没有生成虚构介绍或评论。
- Android主地图定位改用现有 amap_map 的高德定位回调，补齐 APSService、SDK Key 元数据、Wi-Fi状态权限。返回坐标已经是地图坐标，不再要求通过 Web 转换成功才能定位。
- 仅开发静态检查与编译，不运行测试、不操作真机；最终体验由用户验证。
